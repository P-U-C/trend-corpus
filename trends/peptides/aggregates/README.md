# Peptides Aggregates

This directory holds aggregate-only public views of the live peptides runtime
on `city-worker-301`. It exists so that the peptides theme is not a static
demo: the public corpus can show that the runtime is alive, what it is
ingesting, and roughly what shape its claim base is taking, without leaking
any raw claim text, packet question, or per-claim confidence.

## What goes in here

A single JSON file per run, conforming to
`schemas/aggregates.schema.json`. The reference exporter emits
`peptides-aggregates.json`. New windows or new exporters may emit additional
files; all of them must validate against the same schema.

## Privacy boundary

ALLOWED in this directory:

- Counts of claims (total and per-category)
- Entity slugs (lowercase, already public in the extract prompt -- e.g.
  `lilly`, `novo`, `bachem`, `polypeptide`, `hims`, `ro`, `empower`, `fda`,
  `health_canada`)
- Peptide names (lowercase, already public in the extract prompt -- e.g.
  `semaglutide`, `tirzepatide`, `retatrutide`)
- Source URLs (already public in `trends/peptides/sources/`)
- Last-ingested-at timestamps per source
- Window definitions (rolling 30 / 90 / 365 day buckets)
- Schema and generator metadata

NEVER ALLOWED in this directory:

- Raw claim text (the body of the `claim` column)
- Per-claim confidence values
- `date_of_evidence` per individual claim
- Packet questions (the `question` column from `packets`)
- Packet verdicts, body text, or invalidation triggers tied to a specific
  packet
- `superseded_by` relationships (could reveal which claims got contradicted)
- Source `raw_text` content
- Any operator-side identifier (chat IDs, user handles, machine names beyond
  the documented host alias)
- Anything resembling a credential or token

## Suppression rule

The reference exporter respects a `min_count_threshold` (default `3`). Entity
or peptide buckets with mention counts below the threshold are suppressed
(omitted from `top_entities` / `top_peptides`) to prevent re-identification of
low-volume names. This matters when a sector first comes online and the
claim base is small.

## Cadence

Recommended cadence is weekly, NOT hourly. Aggregate-shape doesn't move
fast, and a weekly cadence keeps git history readable. See
`ops/runbooks/peptides-aggregates-bridge.md` for the full deploy contract.

## File listing

- `README.md` -- this file
- `example-aggregates.json` -- a sanitized synthetic example showing the
  intended shape. NOT generated by the live runtime. Useful as a fixture
  for tests and as a reference when other themes copy this pattern.
- `peptides-aggregates.json` -- emitted by the live exporter on
  `city-worker-301`. Absent until the bridge cron is wired up; see the
  runbook.
